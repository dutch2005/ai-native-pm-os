# Module 9.2 — Build a Live Metrics Dashboard in 30 Minutes

**Time:** ~30 minutes  
**Outcome:** A working, stakeholder-shareable metrics dashboard — HTML, no framework, zero build step

---

## Why PMs Build Dashboards

From Reddit r/ProductManagement:
> *"Working with this senior PM feels like working with AI. Documents mostly written by AI, not helpful."*

The antidote: build something real. A working dashboard that pulls live numbers proves your thinking more than any document. It also ends meeting loops — stakeholders can see the data themselves instead of asking you for it every week.

This lesson builds a production-quality Meridian metrics dashboard in a single Claude Code session.

---

## The Build Loop (Review from 9.1)

```
Prompt → Claude generates HTML → you preview in browser → feedback → Claude edits → repeat
```

Target: 3-5 loops to a shareable dashboard. Total time: 20-30 minutes.

---

## The Seed Prompt

```
Build a B2B SaaS metrics dashboard for Meridian OS, a workflow automation 
product. This will be shared with our CEO and Head of Design.

VISUAL REQUIREMENTS:
- Dark theme (#0F1117 background, #1A1D27 card backgrounds)
- Accent color: electric purple (#7B61FF)
- Font: Inter from Google Fonts
- Clean, minimal, data-forward — no decorative elements
- Fully responsive

SECTIONS TO BUILD:

1. HEADER
- Company name: "Meridian OS"
- Subtitle: "Operational Intelligence Dashboard"
- Last updated: today's date

2. KEY METRICS ROW (4 cards, equal width)
- ORR (Orchestration Run Rate): 91,200 / week — trend: ↑8.6% WoW
- Activation Rate: 67% — trend: ↑2pp WoW
- NRR: 118% — trend: →0pp WoW  
- Active Customers: 142 — trend: ↑3 WoW

Each card: metric name, big number, colored trend indicator (green up, red down, grey flat)

3. ACTIVATION FUNNEL (visual bar chart)
Stage: Trial → Setup → First Workflow → 30-Day Active
Values: 100% → 78% → 67% → 54%
Build with pure CSS bars, no external chart library

4. ORR SPARKLINE (6-week trend)
Weeks: W1:68K, W2:71K, W3:75K, W4:79K, W5:84K, W6:91K
Use an SVG line chart — simple, clean

5. ACCOUNT HEALTH TABLE
Columns: Account | ARR | Status (color coded ✅⚠️❌) | Renewal
5 rows of sample enterprise data from Meridian context

6. FOOTER
"Generated by Meridian PM OS — Claude Code"

Build as a single index.html file with all CSS inline.
Save to: CLAUDE-OUTPUTS/prototypes/metrics-dashboard-v1.html
```

---

## Feedback Prompts (Pick the Most Relevant)

**For spacing issues:**
```
The cards feel too cramped. Add more padding inside each card 
and increase the gap between card rows. Target: it should feel 
as spacious as Linear's UI.
```

**For color issues:**
```
The ⚠️ accounts in the table are hard to see. Make the warning 
state use a more visible amber (#F59E0B) with a dark text background. 
Also make the ❌ critical state use red (#EF4444).
```

**For the funnel:**
```
The funnel bars feel flat. Add a subtle gradient to each bar 
going from the accent color at full opacity on the left, 
fading to 60% opacity on the right. 
Also add a percentage label inside each bar, right-aligned.
```

**For adding interactivity:**
```
When the user hovers over a metric card, show a small tooltip 
with the WoW change context: "↑8.6% vs last week (83,988 runs)". 
Pure CSS and JS only, no libraries.
```

## V2: Make It Data-Driven

After V1 is looking good, upgrade it to read from a JSON file:

```
Refactor the dashboard to load data from a JSON file instead of hardcoded values.

Create a data file at: CLAUDE-OUTPUTS/prototypes/meridian-data.json
with the same structure as the current hardcoded values.

The dashboard should fetch this JSON file on load and render all values dynamically.
This way, I can update the JSON weekly and the dashboard reflects the new numbers.

Test: after refactoring, manually change ORR in the JSON to 95000 
and confirm the dashboard shows the updated number.
Save updated files.
```

## What "Good" Looks Like

At the end of this session, you should have:
- A dashboard that loads in < 1 second
- All 6 sections visible without scrolling on a 1440p screen
- Readable on mobile (responsive)
- Numbers that can be updated by editing one JSON file

If someone sent you this URL and you had 30 seconds to review it, you'd have a clear picture of Meridian's health.
